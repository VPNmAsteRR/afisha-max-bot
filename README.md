# Афиша Казачинско-Пировского округа — чат-бот для MAX

Готовый проект по техническому заданию: афиша событий на неделю, семейный досуг
по возрасту ребёнка, ответы на свободные вопросы, администрирование через
Google Таблицу и команды бота, вебхук с HTTPS, резервные копии и передача
заказчику.

## Что реализовано

| Требование ТЗ | Реализация |
|---|---|
| Сценарий А «Афиша на неделю» (п. 3.1) | `app/bot.py::show_catalog`, фильтры, группировка по дням, 5 событий на страницу |
| Сценарий Б «Семейный досуг» | `app/bot.py::show_family`, маппинг возрастов, 18+ не попадает никогда |
| Сценарий В «Свободный вопрос» | `app/search.py`, дни недели с опечатками, «бесплатно», категории, «сегодня/завтра» |
| Модель данных и валидация (п. 3.2) | `app/models.py`, `app/sheet.py`, отчёт по строкам с ошибками |
| Google Таблица + SQLite | `app/sheets.py`, обновление раз в 60 секунд без перезапуска |
| Часовой пояс UTC+7 | `app/dates.py`, неделя с понедельника |
| Администрирование (п. 3.3) | `app/admin.py`: /add, /edit, /del, /list, /check, /reload, /admin |
| Журнал и резервные копии | таблица `audit`, `app/jobs.py` (бэкап базы и снимок таблицы раз в сутки) |
| Уведомления (п. 3.4) | `app/notifications.py`, кнопка «Не присылать анонсы», ограничение скорости |
| Вебхук с HTTPS | `app/main.py`, `deploy/nginx-afisha.conf`, `deploy/install.sh` |
| Стек (п. 6) | Python 3.11+, FastAPI + Uvicorn, APScheduler, SQLite, gspread |
| Ошибки и пустые состояния (п. 4.3) | `app/ui.py`, тексты из ТЗ дословно |
| Демо-данные для прототипа | `python -m app.seed` |

## Регистрация бота в MAX (актуальный порядок, п. 5.1)

Боты создаются только организациями, ИП и самозанятыми — резидентами РФ,
через платформу MAX для партнёров. Бот @MasterBot больше не используется.

1. Ответственный сотрудник регистрируется на `business.max.ru/self`, создаёт
   профиль учреждения и проходит верификацию. Ответственного нужно определить
   до старта работ.
2. В разделе «Чат-боты» нажимает «Создать» и заполняет карточку: логотип
   500×500 px (jpg/png, до 5 МБ), название до 59 символов без эмодзи,
   описание до 200 символов.
3. Никнейм не выбирается: платформа присваивает `id<ИНН>_bot`
   (или `se<id>_bot` для самозанятых). Публичная ссылка —
   `max.ru/id<ИНН>_bot`. Переименовать никнейм нельзя.
4. Модерация — до 48 часов по рабочим дням, уведомления приходят от бота
   «MAX для бизнеса». Пока бот не прошёл модерацию, настройки менять нельзя.
5. После публикации: «Чат-боты» → «...» → «Настройки» → «Получить токен».
   Токен передаётся исполнителю один раз и хранится только в `.env` на сервере.

Лимиты: 5 ботов на организацию или ИП, 2 бота на самозанятого.

## Передача заказчику (п. 5.5)

- `ИНСТРУКЦИЯ_ДЛЯ_ЗАКАЗЧИКА.md` — эксплуатация, админ-команды, типовые сбои,
  чек-лист приёмки из 10 пунктов. Для PDF: `pandoc ИНСТРУКЦИЯ_ДЛЯ_ЗАКАЗЧИКА.md -o инструкция.pdf`.
- Скринкаст 5–7 минут записывает исполнитель: добавление события в таблицу и
  проверка результата в боте.
- Онлайн-созвон 30–40 минут с демонстрацией; запись передаётся заказчику.

## Быстрый старт (5 минут, без Google Таблицы)

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# впишите BOT_TOKEN и ADMIN_IDS (свои ID в MAX), WEBHOOK_URL оставьте пустым

python -m app.seed          # 30–50 тестовых событий на неделю
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

Пустой `WEBHOOK_URL` включает Long Polling — это разрешено только для разработки
и тестирования (п. 5.2 ТЗ). Для рабочего режима обязателен вебхук.

Проверка: откройте бота в MAX, нажмите «Начать» — приветствие с четырьмя
кнопками должно прийти за 1–3 секунды. Если бот не отвечает, смотрите
`data/logs/app.log` и вывод uvicorn.

## Тесты

```bash
pytest -q          # 30 проверок: даты, парсинг таблицы, фильтры, поиск, сценарии, админка
```

## Переменные окружения

Все настройки — в `.env` (шаблон `.env.example`), токен и ID администраторов
не попадают в код и в git.

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен из карточки бота в MAX |
| `WEBHOOK_URL` | публичный HTTPS-адрес, например `https://afisha.example.ru` |
| `WEBHOOK_SECRET` | секрет подписи вебхука |
| `GOOGLE_SHEET_ID` | ID таблицы из её адреса |
| `GOOGLE_CREDENTIALS` | путь к JSON сервисного аккаунта |
| `GOOGLE_SHEET_NAME` | имя листа, по умолчанию «Афиша» |
| `ADMIN_IDS` | до 3 числовых ID через запятую |
| `ADMIN_CHAT_ID` | служебный чат для сводки и сообщений о сбоях |
| `DATA_DIR` | каталог базы, логов и резервных копий |
| `CHANNEL_ID` | необязательно: канал MAX для широких анонсов |

## Подключение Google Таблицы

1. В Google Cloud создайте сервисный аккаунт, включите Google Sheets API,
   скачайте JSON-ключ на сервер (например `/opt/afisha/credentials.json`,
   права `600`).
2. Создайте таблицу с листом «Афиша» и строкой заголовков строго в порядке
   Приложения А (A…M).
3. Откройте доступ к таблице на e-mail сервисного аккаунта (`...@....iam.gserviceaccount.com`)
   с правом «Читатель» (исполнителю достаточно чтения; запись из `/add`
   требует права «Редактор»).
4. Укажите `GOOGLE_SHEET_ID`, перезапустите службу и проверьте `/check`.

Бот перечитывает таблицу каждые 60 секунд и только при изменении содержимого.
Строки со статусом «отменено» в выдачу не попадают, но остаются в базе и
таблице. Строки с незаполненными обязательными полями не показываются, а
попадают в отчёт `/check` с номером строки и перечнем проблем.

## Развёртывание на VPS (Ubuntu)

```bash
sudo bash deploy/install.sh afisha.example.ru
sudo nano /opt/afisha/.env     # BOT_TOKEN, WEBHOOK_URL, ADMIN_IDS
sudo systemctl restart afisha-bot
curl https://afisha.example.ru/health
```

Скрипт ставит пакеты, создаёт пользователя `afisha`, виртуальное окружение,
настраивает nginx и сертификат Let's Encrypt, включает автозапуск через
systemd. Вебхук подписывается автоматически при старте.

Альтернатива — Railway/Render с автоматическим HTTPS: задайте те же переменные
окружения и команду запуска `uvicorn app.main:app --host 0.0.0.0 --port $PORT`.
Перед выбором бесплатного тарифа проверьте, что исходящие запросы на
`platform-api2.max.ru` не блокируются.

## Ограничения платформы, учтённые в коде

- Токен только в заголовке `Authorization`, не в адресе (п. 5.2).
- Вебхук обязателен для работы, Long Polling — только для тестов.
- Не более 2 сообщений в секунду в один диалог и 30 запросов в секунду
  ко всему API: `app/maxapi.py::RateLimiter`, рассылка с паузами.
- Не более 7 кнопок в ряду; кнопки-ссылки — не более 3 в ряду.
- Сообщение не длиннее 3500 символов: `ui.chunk_message`.
- Обработчик вебхука отвечает платформе сразу, обработка — в фоне.
